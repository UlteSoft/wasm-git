# wasm-git 技术白皮书

**版本：** 发行前实现，2026-11-06
**读者：** 审阅人员、编译器工程师、仓库运维人员与集成开发者
**语言：** 简体中文（`zh_CN`）· [English](WHITEPAPER.eu_US.md)

## 摘要

wasm-git 将无损 WebAssembly 更新审计与去中心化内容寻址仓库结合。原始输入字节是主要事实
来源；结构化解释通过 section、函数、控制流、类型化操作数、依赖绑定和可用编译器元数据
说明这些事实。解释可以不完整或存在歧义，但不能因此丢弃原始字节。

客户端与服务端共用原生 Rust 实现。二进制对象、恢复记录与面向人的报告各有用途。
不可变压缩 pack、有界 delta、共享 fork、选择性传输和对象池复制降低历史保存成本，同时
保持原始对象身份。本白皮书说明当前实现的设计依据和保证边界，不宣称完整兼容 Git、验证
程序执行，或能够普遍推断开发者意图。

## 1. 问题与要求

一处源码变化可能导致编译器重排 Wasm 函数、重编号 import、改变 LEB 宽度、重组局部变量
声明或更新调试信息。反过来，极小的二进制修改可能让数值不变的调用索引指向另一个 import。
仅比较反汇编文本，或仅按当前函数索引配对，会掩盖这些区别。

审计需要分别回答：

1. 哪些物理字节发生变化，包括编码选择和未知内容？
2. 哪些声明、函数、块和指令能够解释这些字节？
3. 指令数值字节不变时，引用绑定是否仍发生变化？
4. 哪些对应关系有证据，哪些仍有歧义？
5. 每个被接受的历史版本是否能够独立于结构解释而准确还原？

wasm-git 优先保证证据准确与还原可复现。紧凑显示只是展示方式，不允许从历史中删除原字节。
存储效率依赖二进制 schema、压缩和 delta，而不是把可读 diff 当成权威历史对象。

## 2. 证据与保证模型

### 2.1 物理身份

设 `A`、`B` 为两份被接受的输入字节。补丁合同要求成功创建并应用的补丁能够由 `A` 精确
重建 `B`。应用时核对源摘要、有序编辑范围、旧字节图像、输出长度和目标摘要，全部成功后
才发布结果。

该合同包括语义冗余编码、NaN 位模式、custom payload、重复条目与未知区域，不依赖 WAT
往返、函数配对成功或能够执行该模块的运行时。摘要一致是完整性证据，不是作者身份证明。

### 2.2 结构化解释

扫描器以原文件半开区间 `[start, end)` 记录位置。已知 section 下可包含条目、函数体、
局部变量声明、指令与操作数等嵌套证据。解释引用这些真实范围，不使用重新生成代码的偏移。

字节编辑脚本与函数对应报告回答不同问题：前者提供精确替换证据；后者帮助识别移动、修改
和依赖变化，但不建立唯一历史身份或行为等价证明。

### 2.3 显式不完整性

解析、验证、特性准入和匹配完整性是独立结果。解码器可能理解当前标准配置禁止的编码；
可能读出 section，但验证器拒绝其类型关系；有界匹配可能未考虑全部合理候选。
不能将这些情况合并成一个“支持”标签。

未知 opcode 使立即数长度无法确认时，保留其表达式或函数的剩余字节为 opaque。
后续有独立长度边界的函数和 section 仍可审计。外层 framing 损坏后停止边界发现，不在
任意字节中寻找貌似合理的下一个 section。

## 3. 处理架构

实现分为以下职责：

- **Framing 与物理审计：** 确定已知边界，保留 opaque 范围，比较原字节，输出可重放编辑。
- **类型化 Core 分析：** 将已知声明和操作符投影为内存结构，用于函数及依赖比较。
- **对应关系与结构 diff：** 评估候选、保留歧义，对齐函数、控制结构和指令。
- **元数据解释：** 有界识别 custom 社区约定，将可用调试信息映射回原位置。
- **仓库引擎：** 保存不可变对象，验证对象图，管理引用与工作区，恢复中断的发布。
- **传输与服务：** 认证请求、选择可达数据、协商二进制传输、验证接收状态并授权发布。

各层共用一个库。Cargo feature 决定构建客户端、服务端或两者；默认构建客户端，且不包含
监听服务模块。审计过程不执行 Wasm。

## 4. 更新定位算法

### 4.1 字节对齐

字节 diff 先尝试有界 Myers 插入/删除搜索。精确搜索成功时，`exact_minimal=true` 表示
在该距离模型下取得最小编辑。达到工作量或距离预算后，改用有界内容窗口对齐。
锚点必须在相关比较范围内唯一，并逐字节核对；摘要仅缩小搜索范围，不代替相等性检查。

回退间隙保留完整替换字节，标记 `exact_minimal=false`。非最小脚本仍可精确重建目标。
“最小”不等于源码修改最少、压缩补丁最小，也不等于开发者的概念意图。

### 4.2 函数对应

匹配器结合函数结构、类型、规范化指令特征、依赖证据和导出角色。
已识别 name section 中唯一同名的符号可提高合理候选的权重，但名称不能覆盖与函数体
不相容的证据。

索引平移按重定位处理，不自动视为函数修改。import 与调用身份使用结构字段，避免字符串
拼接歧义。`call`、`return_call`、`ref.func` 的比较带有解析目标、类型与匹配依据。
即使实现本身未变，也单独报告 export 重新绑定。

重复函数体、递归依赖、重名符号和同分候选保持显式歧义。有界相似搜索报告是否完成；
当前同类型候选对上限为 16,777,216。达到上限后，不把尚未确定的端点当成已证实新增或删除。
完整物理字节证据始终可用。

### 4.3 控制结构与指令

结构化比较区分控制块与指令序列，包括嵌套块和兄弟块移动。分支目标在控制上下文中解释，
在证据足够时区分“插入一个块导致标签重编号”和“分支真正改向”。操作数、catch 目标、
`br_table` 默认目标、函数引用和类型化立即数均参与解释。未知或未完整支持的投影不获得
虚构的控制流含义。

审阅应采用最细且可信的范围：对齐完整时看操作数替换；更细对齐不确定时看块或函数变化；
结构无法解码时回到原始字节范围。实现报告证据与限制，不从优化后的代码任意恢复源语句。

### 4.4 section 选择

筛选报告按顶层物理 section 的种类，以及 custom 的精确名称组织候选。
相同内容逐字节验证，重复组保留歧义。位置变化与内容变化分开，前一 section 变长不会被
误报为后续 payload 全部修改。

选择视图有意缩小问题范围：不包含模块头，不重新计算跨 section 绑定或签名输入。
对应 section 可能发生非单调移动，因此不能拼接各组编辑形成整文件补丁。
整模块还原必须使用完整 patch 接口。

## 5. Wasm 演进与自定义数据

Core 1、2、3 的 Core 二进制头版本均为 1，不能用它判断语言特性版本。
所选标准控制准入报告，已知立即数长度仍照常解码。固定版本解析器识别已知提案编码；
特性清单分别标注类型化覆盖、部分 Core 投影、custom 约定、宿主/文本特性和仅外层 framing。
threads 支持指二进制审计与验证，不表示执行线程程序或证明没有数据竞争。

保留的解码特性只增不减。社区状态更新可标记 deprecated，但不得删除读取器，也不得将
历史字节重新解释为不同的编码修订。定期工作流从记录的上游版本生成可审阅元数据更新，
不会自动实现新语法。Component Model 保存原字节和已知外层边界，不宣称完整组件语义验证。

Core 规范定义 custom section 的外层容器；payload 约定由工具社区分别建立。
识别到名称不足以证明其内容遵守预期约定。wasm-git 对 name、producers、target features、
链接元数据、分支提示、源码引用和支持的签名容器提供有界读取器。
未知、不同约定或约定格式损坏的数据保持精确原字节。约定解析失败本身不能作为拒绝无损
存储可接受模块的理由。

DWARF 与链接元数据提供参考性源码位置、内联调用点、符号和受支持变量位置描述。
偏移绑定原模块 SHA-256 与原 code 布局。缺失、冲突、重复或不支持的调试信息均明确报告，
不做猜测。不获取外部调试 URL，也不执行位置表达式。

## 6. 仓库与存储设计

### 6.1 逻辑对象

仓库存储 Wasm、commit 和扁平命名 tree。Wasm payload 是原始二进制；commit 保存单模块
或 tree、按序父 ID、消息、可选显式模块路径和可选作者签名。tree 将规范相对路径映射到
Wasm 对象 ID。目录是隐式的，不采用 Git 的 mode、符号链接和任意文件模型。

对象 ID 是规范类型化二进制 envelope 的 SHA-256。压缩、delta 基底选择和 pack 排列不影响
ID。报告显示十六进制 ID，热对象索引使用原始 32 字节摘要。可变控制与恢复状态使用带版本
的二进制 schema，而非 JSON 或文本引用。

### 6.2 压缩历史

当前 pack 为 `WGTPACK4`，包含排序对象 ID、256 项 fanout、定长记录、逐项 CRC32、
索引 SHA-256 和独立 Zstandard frame。完整对象与块 copy/insert delta 都重建原始 envelope。
写入器评估有界历史/路径候选及实际压缩长度，不承诺全局最优 pack。

候选组保留完整锚点并限制 delta 链。跨 pack 基底可引用保留的共享对象，避免首个私有修订
再存一份完整基底。读取时核对缺失基底、环、整链深度、frame 边界、还原长度和对象摘要。
包含外部 pack 依赖在内，总深度最多为 8。

GC 默认压缩并保留对象。显式 prune 先计算适用引用和恢复根的保留闭包，再重新压缩。
发布完整且同步后的新表示，再移除旧存储。失败可留下冗余不可变对象；保留冗余优于将引用
发布到不完整历史。

### 6.3 共享 fork 与副本

同文件系统 fork 为不可变基础 pack 建立硬链接，拥有独立引用与控制状态。
GC 保留适用共享 pack，只编码私有新增。删除源目录不使 fork 的硬链接失效。
这是文件系统层的数据共享，不是复制一套服务端源码，也不依赖可变的源路径。

对象池向配置节点复制不可变历史。每个拥有者以独立持久引用 pin 需要的提交。
所有节点确认 pin 后才可清除本地内容；读取按源回退，并验证原对象摘要。
fork 获得独立 pin，源拥有者释放自己的 pin 不代表允许删除 fork 历史。
对象池不提供多主引用共识，也不在单个 pool 仓库内部建立独立租户安全边界。

## 7. 分发与发布

HTTP 与 SSH 交换 wasm-git 原生二进制帧和选定对象图。协商省略已验证的现有闭包，使用有界
delta 和分块压缩。浅历史保留真实父 ID，并显式记录本地边界；部分克隆保留提交/tree，
对缺失 Wasm 保存承诺标记，不能把承诺解释成已经验证的空 blob。

补拉核对 envelope、类型、长度和摘要后才安装。bundle 不能引入任意补拉地址；源由本地
显式配置。远端对象读取限于仓库公开的可达内容。浅仓库 push 可借接收端已验证对象补齐，
但发布仍要求完整对象图。

接收过程分别处理认证、仓库/引用授权、对象验证、可选作者信任策略、隔离 hooks 和引用
发布。原子批次复用持久引用事务机制；二进制接收审计记录身份与结果。
网络中断可能使客户端无法确认已经完成的服务器提交，重试前应查询当前引用。

## 8. 性能模型

一个 Rayon 线程池共用于两侧扫描、文件树比较、函数特征、候选评分、压缩和解压。
默认采用进程可用逻辑 CPU；显式线程数可限制共享主机资源。Zstandard 不再创建嵌套线程池。
结果确定性与不同线程数输出一致属于验证内容。

紧凑报告在构造昂贵 JSON 前移除省略字段。仅 custom 的选择视图不解析无关函数。
候选复用已算特征，delta 搜索有界，调试查询使用范围索引。
这些优化减少不必要分配与重复工作，不改变证据合同。

完整 snapshot、图验证及部分传输构造仍将大量对象载入内存。
4 GiB bundle 上限是格式限制，不表示操作只需 4 GiB 内存。
压缩率和耗时必须在记录的 CPU、内存限制下对代表性历史测量。
本白皮书不承诺固定加速倍数，也不声称所有操作达到 Git 耗时。

## 9. 威胁模型与运维边界

上传 Wasm 作为数据处理，服务端不执行它。原生解码器仍处理不可信输入；长度检查、分配
预算、图验证与有界搜索降低风险，但不是形式化安全证明。
Hooks 是管理员选择的可执行程序，需单独进行运行隔离。公开 TLS 由反向代理负责。

内容摘要、传输身份、提交签名和 custom 签名容器各有不同含义。
原生 Ed25519、SSHSIG 与 OpenPGP 提交验证检查签名内容，信任表另行绑定作者与密钥。
外部格式在明确验签或签名准入时执行验证，普通对象读取不执行外部工具。
[WasmHub 手册](WASMHUB.zh_CN.md)定义 PR 审阅与发布门槛。
custom 容器视图可能只报告签名输入变化，并未执行验签。两种机制均不证明程序安全。

能够替换仓库文件的管理员也能够删除数据或更改信任策略。
备份应包含所需对象、引用、承诺状态和 pool 拥有者信息，并分别管理凭据及策略配置。
该服务是仓库后端，不是完整托管网站；用户生命周期、审阅 UI、滥用控制、分布式引用共识和
全部 Git 选项兼容不在当前实现范围内。

## 10. 验证方法

测试应核对独立性质，而非仅让同一路径解析自身输出。
必要检查包括用原字节重放审计编辑、正反补丁、已知函数/源码修改，以及压缩、fork、传输前后
逐个恢复选定历史版本。

合法随机模块补充真实编译器样例。测试应记录生成器版本、种子、输入摘要、合法性验证、
特性/section 覆盖、CPU 绑定、cgroup 限制、单调时钟时长、失败和中断。
可控编译器源码修改提供独立意图判据；无约束随机修改本身不能提供源意图真值。
生成证据全部放在 `.tmp/`，不进入版本化源码。

有限测试中的零还原失败，只说明已完成样本相等，不证明任意输入正确、全部分支覆盖或所有
未来 Wasm 语义得到支持。可复现验证和性能分析方法见[开发指南](DEVELOPMENT.zh_CN.md)。
