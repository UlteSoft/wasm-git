# 人、应用与存储的交互接口

[English](COMMAND_PROTOCOL.eu_US.md) · [文档目录](README.zh_CN.md)

## 三种独立契约

终端摘要、应用响应和仓库存储服务于不同对象。面向人的摘要用于浏览与审阅，
不是供程序解析的 API；应用必须显式选择带版本的传输格式，并检查进程退出状态。
对象、索引、pack、配置状态和网络包继续使用各自的原生二进制格式。
展示格式不会改变对象 ID，也不会重写存储的 Wasm 模块。

Python Web GUI 使用 **`--format binary-v1`** 调用原生客户端，严格校验帧和协议版本，
再按视图筛选必要字段，交给有鉴权的浏览器接口。浏览器 API 的 JSON 仅用于本地传输，
既不是仓库存储，也不是页面组件。页面呈现项目卡片、文件分组、表格和审计面板；
原始输出必须通过单独的主动查看或导出操作取得。

## 格式选择

全局选项放在命令之前：

```sh
wasm-git --format text status /path/to/project
wasm-git --format json status /path/to/project
wasm-git --format binary-v1 inspect module.wasm --json > inspection.bin
wasm-git --format json --threads 8 diff before.wasm after.wasm
wasm-git-server --format json audit-log /srv/wasm-git/receive-audit.bin
```

- `text`：面向人的可打印摘要；长内容和深层集合可能折叠，不是完整审计导出。
- `json`：一个紧凑 UTF-8 响应，末尾一个 LF；命令失败也返回同一结构。
- `binary-v1`：一个带版本的二进制响应，不附加换行。
- `native`：命令本来的输出，包括原始批处理字节及 NUL 分隔的投影；供已有脚本使用。

未指定全局格式时，客户端在 stdout 是终端时使用可读文本，重定向时保留命令原生输出。
应用必须显式选择格式，不能依赖终端检测。独立服务器默认保留原生输出，
包括 readiness 和 stdio 协议。

命令内的选项含义保持独立，例如 `sign-commit --format ssh`、`archive --format tar`、
`for-each-ref --format TEMPLATE`、`diff --format json`。全局机器格式会在没有显式
局部投影时请求结构化 diff、feature、tree、ref 结果。显式局部文本投影返回 `text` 类型。

对象批处理与运行中的 HTTP/stdio 服务有自己的流协议，因此全局 JSON／二进制响应
会在读取批处理输入、启动服务之前拒绝这些操作；应使用 `native`。
`compile-policy`、`compile-protection`、`audit-log`、help 等服务器管理命令支持新响应格式。
尚未选定格式时发生的参数错误、操作系统启动失败、非 UTF-8 参数，仍可能仅写 stderr；
应用必须将响应缺失或无法解码视为失败。

## 版本 1 响应

JSON 与二进制表达同一逻辑记录：

```json
{"protocol":"wasm-git.command","version":1,"command":"status","ok":true,"exit_code":0,"result":{"kind":"data","value":{}},"error":null}
```

示例中的 `value` 被缩略。`result.kind` 可以是带对象／数组 `value` 的 `data`，
带原始文本 `text` 的 `text`，或 `empty`。`command` 仅是命令名称，封装不包含完整参数数组
和环境变量。错误对象包含 `code:"command_failed"` 与 `message`；`ok` 等于退出码是否为零。
非零退出码仍可能附带冲突、部分发布或否定查询结果，不能把所有非零状态当成解码失败。

载荷保留各命令报告自己的 schema 与证据。封装版本不是所有命令字段统一的承诺；
应用仍需识别命令及其局部 schema。应拒绝未知版本和未知结果类型，并核对封装退出码
与子进程退出码。普通命令错误在机器模式下进入响应封装，stderr 保留给底层诊断。

## 二进制布局与字节序

前八字节为 `57 47 54 43 4c 49 00 01`，即 `WGTCLI`、NUL、版本 1。
随后是 **64 位无符号大端**载荷长度，再后是恰好该长度的一个带标签值。
末尾没有校验和、填充、隐式对齐或换行。不得把内存结构体直接强制转换为协议帧；
编码使用显式字节操作，与宿主机大小端和指针宽度无关。

标签占一个字节，布局如下：

- `0`：null；`1`：false；`2`：true；无后续载荷。
- `3`：负的 64 位有符号二补码整数，八个大端字节。
- `4`：64 位无符号整数，八个大端字节；所有非负整数均使用此标签。
- `5`：有限 IEEE-754 binary64 浮点数，八个大端字节。
- `6`：UTF-8 字符串；64 位无符号大端字节长度，随后为字符串字节。
- `7`：数组；64 位无符号大端元素个数，随后依次为带标签值。
- `8`：映射；64 位无符号大端键值对个数。每个键是**不带标签**的长度前缀 UTF-8 字符串，
  后跟带标签值。键唯一，并按 UTF-8 字典序严格递增。

例如 `0x0102030405060708` 编码为标签 `04` 加 `01 02 03 04 05 06 07 08`；
负值 `-0x0102030405060708` 编码为标签 `03` 加 `fe fd fc fb fa f9 f8 f8`；
`-1.125` 编码为标签 `05` 加 `bf f2 00 00 00 00 00 00`。
字符串长度按字节计算，`中文` 两个字符占六个 UTF-8 字节。

这些规则只描述**外层命令响应**。Wasm 指令、LEB128、原始字节范围、对象批处理内容
及嵌入编码不会被交换字节序。审计十六进制字符串保持原始顺序；利用旧／新区间和字节
还原 Wasm，与响应帧本身采用何种字节序无关。

`webgui/protocol.py` 是无依赖的参考解码器，拒绝魔数／版本错误、帧或字段长度不符、
截断、尾随字节、未知标签、非法 UTF-8、非有限浮点数、重复或乱序键、非规范非负有符号整数。
GUI 限制帧为 32 MiB、嵌套为 128 层、值节点为 1,000,000 个；这是消费者资源边界。
其他消费者也应设置自己的限制。大报告可缩小文件／段选择范围，或显式使用有输出上限的原生命令任务。

## 保密与审计保真

机器响应面向可信的本地调用者，可能包含仓库内容、源码标注或诊断细节。
二进制编码既不是加密，也不是脱敏。任意 Wasm 内都可能包含用户敏感内容；
不能声称既无损保留全部证据，又能普遍删除其中所有秘密。

GUI 另设展示边界：默认不返回完整 argv、环境变量、密钥／签名字节和进程工作目录；
已知凭据字段、URL 用户信息、Bearer／Basic 认证值及可识别的敏感赋值会被去除或掩码。
历史与检查界面只返回需要的字段。源码视图不展示嵌入源码正文和构建来源。
指令文本、字节区间、十六进制证据不做静默改写。

原始报告与命令流需要主动确认查看／导出；提示会说明原始用户内容可能包含敏感信息。
命令输出存放于权限受限的临时二进制文件，停止 GUI 后清理。最近项目保存在私有 SQLite
数据库，密码和环境变量覆盖值不进入该数据库。命令参数按数组直接传递，不经过 shell。

GUI 只绑定 loopback，并使用独立会话令牌、Host／Origin／fetch-site 校验、禁用 CORS
及严格 CSP。它是启动用户的本地管理工具，不是可公开部署的多租户服务。
项目身份用于组织操作、防止误把结果应用到其他项目，不等同于 OS 安全主体；
不可信用户或原生插件需要额外的操作系统隔离。

## 验证

Rust 黄金字节测试固定整数、浮点数、UTF-8、集合与帧头编码。
独立 Python 样本验证字节序，并拒绝反转的长度与畸形帧。原生集成测试比较成功、失败、
帮助与否定查询的 JSON／二进制响应，检查 stdout／stderr 分离，利用审计编辑精确还原 Wasm，
并覆盖默认隐藏与主动读取原始输出。另有项目持久化及隔离、只读预览、服务器策略、
接收审计、原始对象流、启动与停止清理测试。
